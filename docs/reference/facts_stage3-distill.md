# stage3-distill

## Stage 3 student initialization  [vitb_unsup_distill.py:132-134; lib/cowreid/encoder.py:37-48; train_finetune_iics.py:35-47; lib/cowreid/iics.py:54-75]
The student is NOT resumed from any earlier SSL checkpoint. It is built fresh each run: DinoV2Backbone(model_name='vit_base_patch14_dinov2.lvd142m', pretrained=True) with ALL parameters frozen, then unfreeze_last(4) re-enables gradients for only the last 4 transformer blocks plus the final LayerNorm (lower blocks stay frozen but still run in the forward graph). On top sits a randomly-initialized FineTuneIICS head = MultiBranchReID(in_dim=768, n_classes_per_cam, proj_dim=256): temporal attention pooling (TemporalPool 'attn', a Linear(768,1) scorer) over T frame features, then Linear(768->256) -> AIBN1d(256) -> ReLU, output L2-normalized (F.normalize dim=1), plus one bias-free cosine classifier nn.Linear(256, k_c, bias=False) per camera. So 'from scratch' means 'pretrained DINOv2 backbone + fresh head', not random weights and not a Stage-2 checkpoint.

## Frozen teacher label inputs (distill/holdout variant)  [vitb_unsup_distill.py:42,77-105 (docstring lines 1-20); lib/cowreid/cluster.py:46-78]
Consumes _vitb_cap_ens5_emb_v1.npz (constant ENS_NPZ). Fields: 'ids' (tracklet-id list) and one (N,D) embedding matrix per seed (every key except 'ids'; 5 seeds per the docstring). Teacher space X_ens = mean over the 5 seed matrices, then row-wise L2 normalization. From this frozen space, computed ONCE at script start (recomputed deterministically on every resume, never refreshed during training): (a) per-camera intra-camera clusters via ClusterAssigner(sim_threshold=0.7, k=10).assign on the teacher embeddings of that camera's tracklets, constrained by same-camera cannot-links; each cluster becomes one proxy with a global index (offset per camera); (b) cross-camera tracklet links via mutual_knn_links(X, cams, k=1). Docstring quantifies: 0.879 intra-cluster pairwise precision, 103 mutual-NN k=1 links at ~60% precision.

## Cross-camera link mining algorithm (mutual_knn_links)  [consensus_ens.py:42-55; vitb_unsup_distill.py:105-114]
Given L2-normalized teacher features X (N,D) and camera labels: S = X X^T; set S[i,i] = -2 and S[i,j] = -2 for all j in the SAME camera as i (cross-camera only); take top-k columns per row (k=1 distill, k=2 deploy); keep pair {i,j} iff j is in i's top-k AND i is in j's top-k (mutual). Returns a set of frozenset pairs of tracklet indices. Links are then lifted to PROXY level: for each tracklet link (a,b), with proxies c_a = intra_global[a], c_b = intra_global[b] and confidence conf = cos(X_n[a], X_n[b]) (teacher-space cosine of the tracklet pair), append (c_b, conf) to plinks[c_a] AND (c_a, conf) to plinks[c_b] (symmetric). Multiple tracklet links between the same proxy pair produce multiple weighted entries — no dedup.

## Pairwise link loss — exact formula  [vitb_unsup_distill.py:195-217]
Training uses two alternating step types by step parity. On odd steps (proxy branch): student embeddings z_i (256-d, L2-normalized) are compared to a non-learnable proxy bank M (n_proxy x 256, L2-normalized rows): s_{i,q} = <z_i, mu_q> / tau with tau = 0.07 (sim = embf @ proxies.clone().t() / args.temp). For instance i assigned to proxy p in camera c: (1) SAME-CAMERA proxy CE: l_i = -log[ exp(s_{i,p}) / sum_{q: cam(q)=c} exp(s_{i,q}) ] — softmax restricted to proxies of camera c only. (2) If p has links, add the pairwise cross-camera pull: with D_c = {q : cam(q) != c} (ALL other-camera proxies, every camera except c), den = logsumexp_{q in D_c} s_{i,q}; l_link = sum_{(o_l, w_l) in plinks[p]} w_l * (den - s_{i,o_l}); l_i += w_link * l_link / max(sum_l w_l, 1e-9), i.e. a confidence-weighted MEAN of per-link cross-entropies -log[ exp(s_{i,o_l}) / sum_{q in D_c} exp(s_{i,q}) ], with w_link = 1.0. Batch loss = mean_i l_i. The pull is instance-embedding-to-linked-proxy, not proxy-to-proxy; `den` is computed once per instance and shared across its links; proxies receive no gradient (plain tensor, requires_grad=False; the .clone() only protects autograd from the in-place momentum update).

## Proxy memory bank: init and momentum update  [vitb_unsup_distill.py:153-165,218; vitb_unsup.py:102-111]
Proxy bank initialized from STUDENT embeddings (not teacher): E0 = embed_tids(...) in eval mode with deterministic linspace frame sampling; mu_p = normalize(mean of E0 over the fixed cluster members of p). Re-initialized this way on EVERY resume — the bank is not saved in the checkpoint. After each odd-step loss, per-instance momentum update with detached features: mu_p <- normalize(m * mu_p + (1-m) * z_i) with m = args.momentum = 0.2. NOTE the convention: momentum multiplies the OLD proxy, so each update keeps only 20% of the old proxy and takes 80% of the new feature (a fast-moving bank). Each of the K=4 instances of a sampled proxy applies this sequentially within the batch.

## Linked-proxy oversampling in the batch sampler  [vitb_unsup_distill.py:183-193]
Odd (proxy) steps build the batch from P=12 proxies: n_link = min(P//2, |linked_pool|) = up to 6 proxies drawn WITHOUT replacement from linked_pool (the sorted set of proxies that appear in plinks), and the remaining P - n_link drawn without replacement from ALL n_proxy proxies via rng.choice(n_proxy, ...) — the second draw can duplicate an already-chosen linked proxy (no dedup between the two draws). For each chosen proxy, K=4 member tracklets are sampled (with replacement iff the cluster has fewer than 4 members), giving a batch of 48 tracklet clips, each of T=2 randomly-sampled frames (i.i.d. with replacement from 8 pre-cached frame paths per tracklet). Comment in code: 'half the sampled proxies come from the linked pool so links fire'.

## Intra-camera CE branch (kept, alternating)  [vitb_unsup_distill.py:168-182; lib/cowreid/iics.py:73-75]
Yes, kept. On EVEN steps: pick one camera uniformly at random; sample up to P=12 of its fixed intra-camera clusters without replacement; K=4 tracklets per cluster (with replacement if needed); loss = standard nn.CrossEntropyLoss on that camera's cosine classifier logits: logits = 16 * <z, W_norm> where W rows are L2-normalized at use (scale=16 fixed) and targets are the fixed local cluster labels. This is a separate full backward+optimizer step — even and odd branches are never mixed in one batch. So the model effectively carries two different temperatures: scale 16 in the CE branch vs 1/0.07 ~= 14.29 in the proxy/link branch.

## Cannot-link handling  [vitb_unsup_distill.py:69,87,95; lib/cowreid/cluster.py:21-43,73-78]
Cannot-links come from build_cannot_link(tracklets, topo, 0.02): pairs that overlap in time AND are either (1) in the same camera, or (2) in a non-overlapping camera pair (spatial-overlap fraction below threshold 0.02 -> different physical locations). In Stage 3 the set is FILTERED to same-camera pairs only (cl_same = {p in cl : both tracklets share a camera}) and used SOLELY as union-find merge constraints inside ClusterAssigner during the one-time intra-camera clustering. There is NO cannot-link term in any training loss, and cross-camera cannot-links are discarded entirely in this stage.

## Training schedule, optimizer, precision  [vitb_unsup_distill.py:49-50,135-151,167-168,219-226]
AdamW with two param groups: backbone trainable params (last 4 ViT blocks + final norm) lr=1e-5, head params lr=3e-4; weight_decay=1e-4 for both; no LR schedule. Mixed precision: torch.autocast fp16 for forward, torch.amp.GradScaler for backward/step; the sim/loss math in the proxy branch is done in fp32 (embf = emb.float()). Loop runs until step >= --target (default 1000 steps total, counting BOTH branch types, so ~500 of each) or the per-invocation wall clock --wall (default 240 SECONDS) expires; checkpoint {model, opt, step} saved at chunk end and resumed by re-running the script (opt state restore is wrapped in try/except and silently skipped on mismatch). No pseudo-label refresh of any kind: clusters, links, and confidences are fixed for the whole run; docstring: 'FIXED all run — no refresh, no drift, no over-merge collapse' and early stop at --target is deliberate ('over-training lesson').

## Holdout vs deployment: data scope  [vitb_unsup_distill.py:83; vitb_unsup.py:40; vitb_unsup_deploy.py:1-14,81-84]
Distill variant (vitb_unsup_distill.py): HOLD = '66.130' (the oblique camera, defined in vitb_unsup.py:40); g_tids excludes all HOLD tracklets, so clustering, link mining, proxies, and both loss branches see only the 6 non-holdout cameras; 66.130 remains a fully unseen query camera for evaluation. Deploy variant (vitb_unsup_deploy.py): g_tids = the 'ids' list of the teacher npz — all 997 embedded tracklets across ALL 7 cameras INCLUDING 66.130; links are mined across all camera pairs so oblique-vs-dorsal alignment is trained explicitly; identities appearing only in 66.130 (~17) lack teacher embeddings and are implicitly excluded. Target metric per docstring = full transductive (best 0.516 at time of writing).

## Holdout vs deployment: teacher and mining differences  [vitb_unsup_deploy.py:38,52-58,74-79,103-109,204-207]
Deploy teacher space differs: loads --teacher-npz default '_vitb_dst_emb_v4.npz' and averages only the matrices whose key contains 's7', 's8', or 's9' (K2 trio — themselves distilled students) or whose key is exactly 't0', then L2-normalizes; this replaces the 5-seed CAP ensemble. Link mining uses k=2 mutual-kNN (--link-k default 2 vs 1 in distill). Deploy also computes and PRINTS link precision against gt labels and counts links involving 66.130 — diagnostic only, gt never enters any loss. Defaults: --seed 10 (vs 5), --ckpt '_vitb_dep_s10_ckpt.pt' (vs '_vitb_dst_s5_ckpt.pt'). Everything else is line-for-line identical: same clustering (0.7, k=10), same proxy construction, same loss formulas, same sampler (n_link = min(6, |linked_pool|)), same P/K/T/temp/momentum/w_link/LRs/target/wall, same alternation; the momentum update is merely inlined instead of being a helper function.

## Data pipeline constants shared by both variants  [vitb_unsup_distill.py:47-48,53,65-74,140; vitb_unsup.py:69-96]

## GOTCHAS
- 'From scratch' means DINOv2-pretrained ViT-B backbone (lvd142m) with only the last 4 blocks + final norm trainable, plus a randomly initialized 256-d head — NOT random weights and NOT a warm start from the Stage-2 SSL checkpoint.
- Momentum convention is inverted relative to most Re-ID memory banks: mu_p <- normalize(0.2*mu_p + 0.8*z). args.momentum=0.2 multiplies the OLD proxy, so the bank keeps only 20% history per update. Writing 'momentum 0.2' with the usual convention (0.2 on the new feature) would be wrong.
- The link term's softmax denominator is over ALL other-camera proxies (every proxy whose camera differs from the instance's camera), not just proxies of the linked camera and not all proxies globally. The same-camera proxy CE, conversely, is over same-camera proxies only. The two softmaxes partition the proxy set per instance.
- The link loss is a confidence-weighted MEAN, not sum: sum_l w_l * CE_l / max(sum_l w_l, 1e-9), with w_l = teacher-space cosine of the original tracklet pair. It is applied instance-to-proxy (pull z_i toward the linked OTHER-camera proxy), never proxy-to-proxy.
- Proxies are a non-learnable buffer (requires_grad=False): gradients flow only through student embeddings; proxies move only via the momentum EMA. The .clone() before the matmul exists purely so the in-place EMA does not corrupt tensors saved for backward — it is not a stop-gradient trick on the loss.
- There is NO pseudo-label refresh at any point: clusters, proxy assignments, links, and confidences are computed once from the frozen teacher npz and stay fixed for all 1000 steps (docstring: 'FIXED all run — no refresh'). However, the proxy BANK is re-initialized from current student embeddings on every resume (it is not stored in the checkpoint), so bank state is not continuous across chunked runs.
- Links are non-transitive by design: they are never union-found into merged clusters. The docstring's stated reason: transitive merging collapses the 60% link precision to ~17% pairwise precision; pairwise use preserves 60%.
- Cannot-links appear ONLY as constraints in the one-time intra-camera clustering (and only the same-camera subset is used); there is no cannot-link/repulsion term in the training loss, and cross-camera cannot-links are unused in Stage 3.
- The two branches alternate by step parity (even = intra-camera CE, odd = proxy CE + link loss) as separate optimizer steps — it is not a weighted multi-task sum in one batch. --target 1000 therefore means ~500 steps of each branch.
- --wall is in SECONDS (240 s per invocation); training to 1000 steps happens across multiple resumed 4-minute chunks. Reporting 240 minutes or treating it as total training time would be wrong.
- Two different effective temperatures coexist: the intra-CE cosine classifier uses fixed logit scale 16 (~tau=0.0625) while the proxy/link branch uses tau=0.07 (~scale 14.3).
- In the odd-step sampler, the 'other' P-n_link proxies are drawn from ALL proxies and can duplicate an already-chosen linked proxy (the two draws are not deduplicated); also n_link is capped by the linked-pool size, so 'half the batch is linked proxies' is an upper bound, exact only when |linked_pool| >= 6.
- Deploy differs from distill in exactly four substantive ways: teacher space (s7/s8/s9 trio mean from _vitb_dst_emb_v4.npz vs 5-seed CAP ensemble _vitb_cap_ens5_emb_v1.npz), tracklet scope (all 7 cameras incl. 66.130 vs 6 with 66.130 held out), link-k (2 vs 1), and seed/ckpt defaults. Loss formulas, sampler, clustering parameters, and all other hyperparameters are line-for-line identical.
- Deploy's printed link precision uses ground-truth labels but ONLY as a diagnostic print; gt never enters any loss — the method remains label-free.
- Link confidence conf is the teacher-space cosine between the two linked TRACKLETS (not between proxy centroids), and the same proxy pair can accumulate multiple (op, conf) entries if several tracklet links connect the same two clusters — each contributes separately to the weighted mean.
- Batch composition numbers: an odd step is 12 proxies x 4 instances = 48 tracklets, each a T=2-frame clip with frames sampled i.i.d. WITH replacement from 8 pre-cached frames; proxy-bank initialization uses eval-mode deterministic (linspace) frame sampling instead.
